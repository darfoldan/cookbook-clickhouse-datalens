# Развертывание ClickHouse®

Если у вас уже есть установленная ClickHouse® версии 26.3.16 и выше, доступная для 
тестовых операций с ресурсами не менее 8 CPU и 32ГБ RAM, переходите к разделу Версии и обновления.

## Yandex Managed Service for ClickHouse®

Подходит, если нет навыков самостоятельного развертывания и администрирования
или нет цели создавать и обслуживать собственную инфраструктуру. Глубоко вникать в настройки не
потребуется: кластер разворачивается с той конфигурацией, которая подходит для
большинства задач.

Этот вариант предоставляет гибкость ресурсов. Класс хоста и объем диска меняются в
несколько кликов, поэтому можно начать пилотный проект на базовых ресурсах и
расширяться по мере роста проекта и объема данных, а не закладывать
инфраструктуру «на вырост» сразу.

Порядок действий в консоли Yandex Cloud:

1. Managed Service for ClickHouse® → **Создать кластер**.
2. **Версия** — последняя с LTS (см. раздел Версии и обновления). В этом рецепте используется версия 26.3.17.
3. **Класс хоста** — минимальный вариант по рекомендациям разработчиков
   ClickHouse®: 8 vCPU, 32 ГБ RAM.
4. **Хранилище** — от пары сотен ГБ. Помимо запаса под данные и мержи, в
   Managed Service for ClickHouse® размер диска напрямую связан со скоростью чтения:
   производительность сетевого диска растет вместе с объемом.
5. **Хосты** — один хост для пилота и типовых задач. При требовании повышенной
   отказоустойчивости — кластерная конфигурация из нескольких хостов с
   ClickHouse® Keeper на отдельном хосте для нагруженных систем.
6. **Настройки СУБД и пользователь** — задать имя и пароль пользователя, имя базы
   данных и выбрать метод управления пользователями и базой. Для BI понадобится завести
   отдельного пользователя с правами только на чтение нужной БД, его можно добавить позже.
8. **Сервисные настройки** — включить доступ из DataLens и доступ из WebSQL.
9. **Настройки пользователей по умолчанию** — включение
   анализатора (enableAnalyzer) вынесено в эту группу настроек. Включите эту функцию.

## Самостоятельная установка

Для самостоятельной установки ClickHouse® используйте официальный репозиторий (`apt`/`yum`)
или официальный Docker®-образ. Дальше в рецепте разницы нет: все описанное
одинаково работает и в Managed Service for ClickHouse®, и на собственной инсталляции.
Внимание: анализатор должен быть включен `SELECT getSetting('enable_analyzer')`. 
Если настройка выключена для всего сервера, вы можете включить ее для отдельного 
пользователя или профиля `ALTER USER user MODIFY SETTING enable_analyzer = 1`.

## Версии и обновления

Устанавливайте свежие версии и следите за обновлениями. Релизы выходят ежемесячно, и
заметная доля изменений — это оптимизация именно тех сценариев, которые
генерирует BI: агрегации, `JOIN`, `DISTINCT`, фильтрация по ключу сортировки,
работа проекций. Отставание от свежей версии на год-полтора может вызывать проблемы с производительностью, которые уже решены в новых версиях.

Но «свежая» не значит «только что вышедшая»:

- Выбирайте версию LTS, с релиза которой прошло 2–3 месяца: за это время
  устраняются основные проблемы релиза. То есть не 26.3.1, а 26.3.17 в июле 2026. 
- Продуктив — плановое обновление на следующую LTS по той же логике. 
- Перед обновлением просматривайте [changelog](https://github.com/ClickHouse/ClickHouse/tree/master/docs/changelogs), в первую очередь раздел Backward
  Incompatible Changes.

## База данных и права пользователя

Для целей этого рецепта стоит создать отдельную базу данных и 
пользователя. В собственной установке или если в Managed Service for ClickHouse® выбран режим управления пользователями 
через SQL, пользователю нужно выдать права:
`GRANT SELECT, INSERT, ALTER TABLE, ALTER VIEW, CREATE TABLE, CREATE VIEW, CREATE DICTIONARY, DROP TABLE, DROP VIEW, TRUNCATE, dictGet, OPTIMIZE ON <имя базы>.* TO <имя пользователя>`. В Managed Service for ClickHouse® настройка более грубая.
