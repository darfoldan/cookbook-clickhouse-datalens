# Развертывание ClickHouse®
{% note info %}


Если у вас уже есть установленная СУБД ClickHouse® версии 26.3.16 и выше, доступная для 
тестовых операций с ресурсами не менее 8 CPU и 32 ГБ RAM, переходите к разделу [Версии и обновления](ДОБАВИТЬ ССЫЛКУ НА РАЗДЕЛ).


{% endnote %}


В этом рецепте вы рассмотрите два варианта развертывания ClickHouse®: облачный сервис Yandex Managed Service for ClickHouse® и самостоятельную установку.

## Yandex Managed Service for ClickHouse®

Подходит, если нет навыков самостоятельного развертывания и администрирования
или не нужно создавать и обслуживать собственную инфраструктуру. Глубоко вникать в настройки не
потребуется: кластер будет развернут с конфигурацией, которая подходит для
большинства задач.

Этот вариант обеспечивает гибкость ресурсов. Класс хоста и объем диска легко изменить, поэтому можно начать пилотный проект на базовой конфигурации и
увеличивать ресурсы по мере роста проекта и объема данных, а не закладывать
инфраструктуру «на вырост».

### Порядок действий в консоли Yandex Cloud

1. Перейдите на страницу создания кластера: Yandex Managed Service for ClickHouse® → **Создать кластер**.
2. **Версия**: выберите последнюю LTS (см. раздел [Версии и обновления](ДОБАВИТЬ ССЫЛКУ)). В этом рецепте используется версия 26.3.17.
3. **Класс хоста**: выберите минимальную конфигурацию по рекомендациям разработчиков
   ClickHouse®: 8 vCPU, 32 ГБ RAM.
4. **Хранилище**: от 200 ГБ и выше. Учитывайте не только объем для хранения данных и слияний (merges, мержи). В Yandex Managed Service for ClickHouse® размер диска влияет на скорость чтения:
   производительность сетевого диска растет вместе с объемом.
5. **Хосты**: создайте один хост для пилота и типовых задач. Если требуется повышенная отказоустойчивость, используйте кластерную конфигурацию из нескольких хостов с
   ClickHouse® Keeper на отдельном хосте для нагруженных систем.
6. **Настройки СУБД и пользователь**: задайте имя и пароль пользователя, имя базы
   данных и выберите метод управления пользователями и базой. Для BI-системы понадобится создать
   отдельного пользователя с правами только на чтение нужной БД, его можно добавить позже.
8. **Сервисные настройки**: включите доступ из Yandex DataLens и доступ из WebSQL.
9. **Настройки пользователей по умолчанию**: включите функцию  анализатора (`enableAnalyzer`).

## Самостоятельная установка

Для самостоятельной установки ClickHouse® используйте официальный репозиторий (`apt`/`yum`)
или официальный Docker®-образ. Дальше в шагах рецепта разницы нет: все описанное
одинаково работает и в Yandex Managed Service for ClickHouse®, и в on-premises-инсталляции.

{% note warning %}

Анализатор должен быть включен: `SELECT getSetting('enable_analyzer')`. 

Если настройка выключена для всего сервера, вы можете включить ее для отдельного 
пользователя или профиля: `ALTER USER user MODIFY SETTING enable_analyzer = 1`.


{% endnote %}

## Версии и обновления

Устанавливайте свежие версии и следите за обновлениями. Релизы выходят ежемесячно, и
заметная доля изменений — это оптимизация именно тех сценариев, которые
генерирует BI-система: агрегаций, `JOIN`, `DISTINCT`, фильтраций по ключу сортировки,
работы проекций. Отставание от свежей версии на год или полтора может вызывать проблемы с производительностью.

Но «свежая» версия не значит «только что вышедшая»:

- Выбирайте версию LTS, с релиза которой прошло 2–3 месяца: за это время
  возможные проблемы успевают устранить. Например, в июле 2026 года стоит выбрать не версию 26.3.1, а версию 26.3.17. 
- Для промышленной эксплуатации настройте плановое обновление до следующей LTS-версии по той же логике. 
- Перед обновлением просматривайте [changelog](https://github.com/ClickHouse/ClickHouse/tree/master/docs/changelogs), в первую очередь — раздел Backward
  Incompatible Changes.

## База данных и права пользователя

Для этого рецепта стоит создать отдельную базу данных и 
пользователя. В собственной установке или в режиме управления пользователями через SQL в Yandex Managed Service for ClickHouse® пользователю нужно выдать права: `GRANT SELECT, INSERT, ALTER TABLE, ALTER VIEW, CREATE TABLE, CREATE VIEW, CREATE DICTIONARY, DROP TABLE, DROP VIEW, TRUNCATE, dictGet, OPTIMIZE ON <имя базы>.* TO <имя пользователя>`. Если в Yandex Managed Service for ClickHouse® опция управления через SQL выключена, то настройка прав и ролей в интерфейсе будет более грубой. 

## Итоги

Вы разобрались, как развернуть и подготовить к дальнейшей работе ClickHouse®. 

Что важно запомнить:

- ClickHouse® можно развернуть в Yandex Managed Service for ClickHouse® или установить самостоятельно.
- В Yandex Managed Service for ClickHouse® можно начать с базовой конфигурации и увеличивать ресурсы по мере роста проекта и объема данных.
- Выбирайте LTS-версию, с релиза которой прошло 2–3 месяца, и планируйте обновление до следующих LTS-версий.
- Чтобы выполнять инструкции из рецептов, создайте отдельную базу данных и пользователя с необходимыми правами.
