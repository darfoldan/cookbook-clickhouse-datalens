# Построение оптимальной витрины в ClickHouse® для работы в Yandex DataLens

В этом сборнике рецептов вы спроектируете и подготовите данные в ClickHouse® для аналитики в Yandex DataLens: создадите базовую таблицу, настроите ее под типовые BI-запросы, при необходимости добавите дополнительные структуры для ускорения запросов и подготовите производные данные для аналитики. Затем вы сможете подключить подготовленные данные к Yandex DataLens и оценить BI-нагрузку на ClickHouse®.

Практические примеры выполняются последовательно: в каждом рецепте используются таблицы и объекты, созданные в предыдущих. Сначала вы создадите базовую таблицу и проверите ее на типовых запросах.

Затем вы разберете, какой способ оптимизации подходит для какой задачи:

- для запросов, которые плохо обслуживает основной порядок сортировки данных `ORDER BY`, рассмотрите [проекции](04-nastroyka-tablits-proektsii.md);
- для отдельных сценариев фильтрации — [индексы пропуска данных](05-nastroyka-tablits-skip-indeksy.md);
- для работы со справочными данными — `JOIN` и [словари](06-ispolzovanie-tablits-join-i-slovari.md);
- для производных показателей и предварительных расчетов — [представления](07-ispolzovanie-tablits-predstavleniya-i-okonnye-funktsii.md) и [материализованные представления](08-proizvodnye-tablitsy-materializovannye-predstavleniya.md).

Все примеры выполняются на одном сквозном наборе данных: таблица `financial_transactions` на 50 млн строк.

## Содержание сборника

1. **Построение оптимальной витрины в ClickHouse® для работы в Yandex DataLens** — познакомитесь с подходом к подготовке данных для BI-аналитики и узнаете, как устроен сборник рецептов.
2. **Развертывание ClickHouse®** — развернете ClickHouse® в Yandex Cloud или самостоятельно и подготовите окружение для работы.
3. **Проектирование и подготовка таблиц** — создадите базовую таблицу, настроите сортировку и партиционирование и проверите производительность запросов.
4. **Настройка таблиц. Проекции** — узнаете, как ускорять запросы с помощью проекций и проверять их эффективность.
5. **Настройка таблиц. Индексы пропуска данных** — научитесь использовать индексы пропуска данных для сокращения объема данных, читаемых при фильтрации.
6. **Использование таблиц. JOIN и словари** — рассмотрите способы обогащения данных из справочников и сравните производительность `JOIN` и словарей.
7. **Использование таблиц. Представления и оконные функции** — создадите представление с оконными функциями для расчета производных показателей и оцените стоимость вычислений.
8. **Производные таблицы. Материализованные представления** — научитесь заранее рассчитывать агрегаты с помощью инкрементальных и обновляемых материализованных представлений.
9. **Использование таблиц и витрин в Yandex DataLens** — подключите подготовленные данные к Yandex DataLens, создадите датасет и чарт и настроите параметризацию.
10. **Мониторинг BI-нагрузки** — научитесь отслеживать нагрузку на ClickHouse®, находить ресурсоемкие запросы и оценивать их влияние на производительность.

Сборник посвящен оптимизации данных и запросов на стороне ClickHouse®. На производительность аналитики влияют настройки самой Yandex DataLens: структура датасетов, количество чартов и селекторов, кеширование и другие параметры. Рекомендации по их настройке вы найдете в статье [Рекомендации по оптимизации в Yandex DataLens](https://yandex.cloud/ru/docs/datalens/concepts/optimization_recommendations).

## Почему для BI-системы используют колоночную СУБД

- Профиль нагрузки BI-системы — OLAP: агрегации идут по сотням миллионов строк, при этом в запросе участвуют единицы колонок из десятков имеющихся. Так устроен почти любой график: одно-два измерения, одна-две меры.
- Строковая СУБД читает строку целиком, включая ненужные запросу колонки. Колоночная читает только затронутые колонки — объем чтения падает пропорционально доле используемых полей.
- В пределах колонки данные однородны, поэтому общие алгоритмы сжатия (LZ4, ZSTD) дают заметно лучший результат, чем на строковом представлении, а специализированные кодеки (Delta, DoubleDelta, Gorilla, T64) дожимают монотонные ряды. Это позволяет сэкономить дисковое пространство и ускорить чтение.
- Обработка выполняется блоками (векторизация) с эффективным использованием кешей CPU.

В итоге при одинаковых ресурсах колоночная СУБД может работать в несколько раз быстрее строковой. ClickHouse® позволяет реализовать такой подход. Среди преимуществ ClickHouse® — открытый исходный код, линейное масштабирование и нативный коннектор для Yandex DataLens.

## Чек-лист подготовки данных для Yandex DataLens

- Настройте `ORDER BY` и `PRIMARY KEY` под реальные паттерны фильтрации.
- Если для управления данными нужно партиционирование, настройте его так, чтобы количество партиций не было избыточным.
- Проверьте базовую таблицу на типовых BI-запросах и по результатам определите, нужна ли дополнительная оптимизация.
- Если для запросов нужен другой порядок сортировки, заранее подготовленные агрегаты или дополнительный способ поиска по отдельным полям, используйте проекции.
- Если нужно ускорить фильтрацию по колонкам с подходящим распределением значений и хорошей корреляцией с `ORDER BY`, используйте индексы пропуска данных.
- Если для аналитики нужны данные из отдельных справочников, используйте `JOIN` или словари.
- Если для аналитики нужны производные показатели, которые можно рассчитывать при запросе, используйте представления `VIEW`.
- Если рассчитывать производные показатели при каждом обращении к `VIEW` слишком затратно, подготовьте результаты заранее с помощью материализованных представлений.
- Если агрегаты нужно обновлять при каждом `INSERT`, используйте инкрементальное материализованное представление; если нужен полный пересчет по расписанию — обновляемое материализованное представление.
- После подключения к Yandex DataLens проверьте реальную BI-нагрузку с учетом запросов от чартов и селекторов.
